# Consumer adoption

## Ruby

During local/path-based rollout, consumers use:

```ruby
gem "foaf_client", path: ENV.fetch(
  "FOAF_CLIENT_GEM_PATH",
  File.expand_path("../../foaf-client/gem", __dir__)
)
```

Docker builds supply the repository as the named BuildKit context
`foaf_client` and copy `gem/` to `/foaf-client/gem`. A deployment host must
therefore check out `foaf-client` at the sibling path expected by its compose
file until the gem is moved to a Git source or private registry.

The package deliberately owns `Foaf::LedgerClient`, `Foaf::ClientConfig`, and
`Foaf::LedgerSigner`. It does not define `Foaf::Client`, `Foaf::Config`, or
`Foaf::Signer`, because existing Rails apps own those constants.

## TypeScript

From `client/`:

```bash
./scripts/sync-to-app.sh /absolute/path/to/app
./scripts/check-drift.sh /absolute/path/to/app
```

The target is replaced with `rsync --delete`, every source file receives an
AUTOGENERATED header, and `SOURCE.md` records the source repository.

## Rollout flags

GrowOperative uses independent flags so every step can be reverted:

- `FOAF_SHARED_READS=true` returns shared ledger reads after shadow-diffing
  them against the legacy response.
- `FOAF_SHARED_AUTH_VERIFIER=true` routes RS256 tokens through the shared auth
  verifier; the application’s temporary HS256 bridge stays separate.
- `FOAF_SHARED_WRITES=true` routes trustline updates and pending-transfer
  create/confirm/reject calls through the shared ledger client. Writes are
  single-run and never fall through to the legacy transport after a failure,
  avoiding duplicate mutations after an ambiguous network response. Set the
  flag to `false` to restore the legacy transport for subsequent requests.
- `EXPO_PUBLIC_FOAF_SHARED_TRUSTLINE_CARDS=true` selects the shared trustline
  card while keeping GrowOperative’s Redux state and callbacks.

GrowOperative unwraps successful shared write envelopes back to its established
parsed-body shape, so the settlement and replay state machines do not change.
Failures retain their upstream status and body in the Rails warning log and
return `nil`, matching the legacy call-site contract. Confirmation and
rejection are signed by the receiving user’s locally stored FOAF key.

### GrowOperative shared-write rollout

The Phase-5 write checkpoint was approved on 2026-07-24. Local development
enables `FOAF_SHARED_WRITES` in Compose so normal trade flows exercise the
shared transport. Deployed environments remain disabled unless their env file
explicitly opts in.

Roll out demo before production:

1. Confirm `/v1/debug/foaf/status` reports FOAF reachable.
2. Set `FOAF_SHARED_WRITES=true` in the target backend env file and recreate
   the backend container; a restart alone does not reload environment values.
3. Run the trade test and inspect `/v1/debug/foaf/reconcile`. Credloop-cancelled
   differences are expected; unlinked trustlines are not.
4. To roll back subsequent writes, set the flag to `false` and recreate the
   backend container. Do not switch transports within a request or retry a
   failed shared mutation through legacy.
